# 进益资本实验迭代

用于本项目的“设计实验 → 训练与验证/测试 → 比较历史版本 → 整理改善候选 → Git 推送”。用户只请求某一阶段时，只执行该阶段和必要前置工作。技能本身不启动训练，也不把成绩反馈解释为新一轮实验。

本技能随 jycapital 仓库保存。本仓库及子目录中的“实验”“模型”“版本”“训练”“评估”“成绩”“提交材料”默认指向本项目，结合请求语义选择相应阶段，不要求用户重复项目名或 `$jycapital-experiment`。仓库 `AGENTS.md` 明确要求在相关任务中读取本技能；与实验流程无关的任务不触发完整流程。

## 已确定的工作约定

- 比较参照是本地验证集最优、平台最优（已有可信平台分时）、父版本（存在时）。不额外固定一个永久 v1 比较位。
- 每个完成训练的版本都评估验证集和测试集，包括没有改善的版本。checkpoint 仍按验证集选择。
- 只为改善候选新增 `submissions/<run_id>/`。其他实验保留代码、指标和比较结论。
- 默认一个设计方案、一次正式训练运行。用户明确要求沿某方向多次尝试时，必须有次数或时间预算。
- 提交材料放在仓库根目录 `submissions/` 并纳入 Git；不生成 ZIP。比赛平台提交由用户执行。
- 每版平台提交尽量减少文件数量，全部附件必须为 UTF-8 文本（如 `.ipynb`、`.py`、`.json`）。权重用完整精度数值数组保存；不提交 `.pt`、`.pth`、`.npz` 等二进制附件。合并配置、统计量和源码，说明与依赖可内嵌 Notebook；清单与验证报告优先保存在 `experiments/`。
- 平台提交代码不添加文件、源码或权重的哈希／附件匹配校验；哈希仅用于本地追溯和提交前核验，平台问题由用户另行排查。
- 平台成绩可由用户提供，或使用已接入的 [平台查分技能](../jycapital-scores/SKILL.md) 查询；沿用已有认证配置，无需再次索要接口。没有平台分不阻塞本地实验。
- 持续训练、验证和预测使用后台进程监控。正常进度不频繁唤醒 LLM；仅每小时、用户询问、训练／预测结束或异常时检查并报告。

## 1. 确定上下文与范围

从当前工作目录识别 jycapital 仓库，先读 `AGENTS.md`、`docs/README.md`、`docs/development.md`、当前评估协议及实验/提交索引。环境或字段约定不明确时，按阶段读取 [仓库约定与工具限制](references/repository.md)。不要把本机绝对路径当成其他环境的固定路径。

明确本次研究方向、方案版本、父版本（可为空）、使用的协议和用户要求的交付阶段。模型结构、数据处理、损失、训练方法和推理方式都可以是实验变量；不把新实验限制成改配置。

在训练前从已完成历史运行中选定比较参照，记录 run_id；排除当前新运行。读取 [比较与候选判定](references/comparison.md) 处理参照、分数和晋级条件。

已确定的约定不反复询问。只有影响结论或执行范围的缺口才先讨论，例如改变评估区间/标签/主指标、成绩无法对应到模型、放宽覆盖要求、使用未明确允许的输入或多次尝试缺少预算；同时可继续不依赖答案的准备工作。

## 2. 设计与实现

在方案说明中记录研究假设、父版本、主要改动、验证方法和预期计算开销。多个部分一起改变时，只主张整体方案效果；需要归因时再做用户授权范围内的消融实验。

在 `solutions/<version>/` 组织完整方案，使模型与其数据处理绑定。普通配置/种子变化可以属于同一方案的不同 run。保持历史方案及已导出目录可追溯；执行新版本前适配快照、训练、比较、导出和验证工具中的版本路径。

先验证现有 Python 环境、依赖和 GPU 可用性，再补安装缺失项。复用正常工作的本地训练环境，不因模型版本变化盲目重装大型依赖。

运行前检查因果对齐、标签边界、输出约定及当前改动涉及的关键行为。保存完整生效配置、协议、随机种子、数据指纹、环境和实际源码快照；有未提交改动时如实记录，不能只保存 HEAD 充当实际源码。

## 3. 训练并评估每个版本

沿用仓库当前协议的训练/验证/测试划分，禁止为获得更好分数悄悄改区间或样本。拟合型预处理仅在训练范围拟合，或使用预测时点已知的因果窗口统计。

按验证集主指标选择 checkpoint 并冻结，再对该权重计算本版本测试集指标；无改善也要完成测试评估。不要从多个 epoch 中挑测试分最高的权重。每版都会观察测试结果，因此不得把长期迭代后的测试结果描述成从未参与研究观察的最终盲测。

保留逐轮损失、验证指标、最佳轮次、停止原因、训练曲线、权重及可复现的处理记录；保留验证/测试预测、逐截面指标和逐月汇总。详细过程与预测存于忽略的 `outputs/runs/<run_id>/`，仓库文档只保留方法、有效结论、必要来源和局限。

失败或预算终止的运行如实记为失败/未完成，保留已有证据，不填造缺失指标，也不作为历史最优或提交候选。

### 后台监控与唤醒

启动持续训练或预测前，按 [后台监控约定](references/monitoring.md) 安排独立监控进程和可用的通知通道；已有运行直接接入监控，不重启训练。进程存活、日志增量与状态文件由后台程序检查，普通月份、batch、epoch 或预测分片完成只更新本地状态，不为这些进度反复调用／唤醒 LLM，也不逐项发送对话消息。

正常运行每满一小时汇总检查一次；用户询问时立即读取当前状态并回答；训练／预测结束、进程异常退出、明确错误或达到按阶段设置的停滞阈值时立即唤醒检查。同一异常合并去重，停滞提示不直接等同于失败；监控不得自行换参数、重训或终止任务。用户另行指定频率时按其要求执行。

监控日志与状态放在忽略的运行目录。只有当前通知路径已通过“主对话空闲后收到后台通知并自动开始新回合”的验收，才能声称会自动唤醒 LLM；接口接受消息或写入本地通知文件不等于自动恢复执行。不同发送路径分别验收。没有独立回调能力或尚未通过空闲验收时，保留一次等待后台通知的工具调用，由编排层内部等待，不以 LLM 的短周期轮询代替后台监控。训练结束后继续完成本次已授权的评估、比较及条件导出。

## 4. 比较并作出候选结论

按 [比较与候选判定](references/comparison.md) 检查可比性，输出新版本与三类参照的数值、差值、逐月表现、覆盖率和资源代价；参照相同时合并展示但保留角色。

当前默认主指标是协议中的验证集 `rank_ic_mean`，越高越好。在可比性和输出检查通过、覆盖率不降低的前提下，超过本地验证历史最优才认定为默认的改善候选。没有另行约定时，不凭空增加“必须提升百分之几”的阈值；单种子微小提升标为初步证据，不能宣称统计显著。

测试集、其他指标和开销的退化必须报告，不能只挑好的数字。仅超过父版本但未超过本地验证最优，不作为默认导出理由。需要采用其他晋级标准或接受覆盖率下降时，先与用户讨论。

没有改善时，输出对比与原因，保留实验并按本次授权更新/推送代码及摘要；不新增提交目录，不为了得到正向结论自动开始另一个方案。

## 5. 导出与验证改善候选

从选定运行的冻结源码、配置、预处理状态和权重导出到根目录 `submissions/<run_id>/`，默认拒绝覆盖已有候选。用户明确要求重新打包时可替换该目录，保留旧材料的 Git 历史或本地备份，并更新清单与索引；不得因此改变所选权重和本地评估结论。不要把旧权重与当前工作区的新模型代码混合。

按实际依赖收集唯一推理 Notebook、训练与推理代码、配置、随机种子、完整权重和依赖声明，在保留复现能力的前提下合并文本附件。优先采用一个 Notebook 加一个合并参数 JSON；不为追溯元数据、每种频率或每个内部模块额外增加平台文件。无需沿用历史版本的文件数量或推理后端。

本地训练仍可使用二进制 checkpoint，但导出权重须转换为真正的文本数值，保留 dtype、shape 和恢复所需精度，不将二进制文件改扩展名或包装为编码字符串。逐张量核对恢复后的 dtype、形状和数值，并验证仅靠提交目录中的文本文件即可推理；运行时不得依赖仓库源码、外部权重下载或临时生成 `.pt` 文件。

Notebook 提供 `main(datasources, start_date, end_date)`，末尾加入有 `if __name__ == "__main__":` 保护的短区间调试单元格。调试时显示行数、类型和预览并检查输出，Git 中不保存执行输出。真实推理通过 `datasources` 获取行情表，不能在评测入口硬编码开发表；调试单元格可显式传入开发表。

检查导入 Notebook 不会自动查询行情，手动调试能执行，输出为 `date、instrument、factor`，值有限、键唯一、时间范围正确、覆盖满足协议。验证附件路径、权重与推理一致性及具有代表性的完整区间推理；结论限定为实际验证的环境与范围。

更新逐文件哈希、提交清单和提交索引；确保 Git 检出后字节与哈希一致。目录包含要交付的模型参数，不包含行情、离线预测答案、本地 `dai.py`、凭据、缓存或训练环境。

## 6. 记录、推送与反馈

更新实验索引及可入库的结果/比较摘要，记录参照 run_id、晋级依据、局限和产物位置；候选另更新提交索引和文档索引。未改善和失败实验也留记录，避免只保存成功结果。

当用户请求本技能的完整流程或已授权 commit/push 时，检查具体提交范围及远程分支，提交并推送到仓库约定的远程；当前约定为 `origin/master`。检查推送结果及本地/远程 HEAD。只请求设计、训练或成绩回填时，不自行扩大到 Git 推送；不把向 GitHub 推送等同于向比赛平台提交。

最终报告：本次改动、验证/测试对比、三类参照、是否改善及证据强度、是否导出及目录、已执行的检查、Git 提交/推送状态、剩余平台验证事项。未推送或未完成就明确说明，不把待办写成完成。

用户请求查询平台分时使用 [平台查分技能](../jycapital-scores/SKILL.md)。只查看时报告查询结果；请求回填或提供成绩反馈时，按 [平台成绩回填](references/comparison.md#平台成绩回填) 绑定到准确的 submission/run/权重，更新平台最优参照。只确认“平台可以运行”时，只更新运行状态，不能据此填写官方分或宣称正式提交通过。

## 多次尝试的预算

只有用户明确要求多次改进时才进入循环。开始前明确次数上限或墙钟时间预算；缺失则先询问，不把“尽量改好”视为无限额度。用户指定两种上限时，以先达到者为准。

记录每次正式训练尝试，包括失败的尝试、换参数和换种子，避免用重试绕过上限。默认单方案中的必要实现修复不算额外研究方向，但实际训练尝试和耗时仍如实记录。

预算范围默认覆盖本轮设计、训练、验证/测试和交付，开始前记录截止时间并为评估、保存结果和推送预留时间。临近截止不启动明显无法完成的新训练；到期停止耗时工作，保存可保存的状态并报告未完成项，不擅自延长预算。逐次产出比较结论，最终只导出本轮达到改善条件的最佳候选；若没有改善，保留本轮结果并结束。
