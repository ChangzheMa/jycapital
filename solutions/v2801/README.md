# v2801：完整神经历史表示与梯度提升树

v280x新系列首版，run为`v2801-neural-tree-s42`。固定使用父版[v2401](../v2401/README.md)的第4轮EMA，保留全部因果历史编码，再用树学习对主预测的条件补充。父网络 **2,641,743个参数**保持不变；新树最多1,200棵、深度6，最多152,400个分裂阈值及叶值。2026-10-24（UTC+08:00）已完成正式双集评估，选中25棵树，双集IC略升、Rank IC下降；fast材料已导出，详见下方冻结结果。

## 研究假设

[研究依据](../../docs/neural-tree-research-20261024.md)审查TabArena、BeyondArena以及2026年的Grables和NPBoost，区分表格／关系任务的证据与本项目的分钟收益目标。现有主要方案使用平滑神经预测映射，本版检验学习阈值组合的树预测器能否补充它；没有采用外部模型或外部数据，也不使用论文中的带标签推理上下文。

v2301同时缩短历史并替换预测结构后退步，本版因此保留v2401完整三频历史。v2501仅小幅改善其父版，v2601市场条件未改善，本版不叠加这些模块，也不默认采用尚无完整结果的v2701输入变化。

## 表示与预测

每个股票日共享父网络编码，八个时点分别取得：

| 内容 | 维度 | 来源 |
| --- | ---: | --- |
| 融合表示 | 384 | v2401完整因果历史和价格读取后的共享隐藏表示 |
| 三频当前原输入 | 231 | 每频最后可见规则槽位的原77通道，缺失槽位保留原标志 |
| 时点编码 | 8 | 原有八时点one-hot |
| 父主预测 | 1 | 原收益主头 |

共 **624维**。这里的原输入沿用原z、价格共同坐标、数量c、有效性和FP32价格中心，未新增手工技术指标；没有把完整历史缩成当前槽位。神经权重不进入优化器，特征提取使用`inference_mode`，并核对提取前后张量指纹。保留父参数的grad标志，使CPU沿用相同推理算子；这不表示训练神经权重。

树的初始预测固定为父主预测，目标仍是已有`vwap_return`的原截面标准化值。最终预测为父预测与树输出之和；不重算、替换或反推标签，不读取exposure。树采用平方误差，日期衰减沿用730日半衰期和0.25下限，按全部有效训练样本归一化到平均权重1。这与父网络的批内归约和Huber目标不同，整体试验不能单独归因预测器。

固定配置为XGBoost **3.2.0**、GPU `hist`、64个分箱、深度6、学习率0.03、最小叶权重512、L2为10，行／列抽样各0.8。每25棵树为一个验证块，最多48块；按验证IC严格新高选择，使用统一动态早停。第0块的父预测也参与选择，所以若新树没有帮助，可以保留零棵树。测试只在选择冻结后执行。

模型JSON不能完整恢复行列抽样器的隐藏状态。因此正常运行和恢复都在每个验证块边界重建提升器，并使用`42 + 块编号`作为该块种子；块内保留原抽样和全局迭代编号。CPU检查确认中断后的树、预测、选择和损失记录一致。块边界会重建原生预测缓存，实际耗时须包含这项成本，不把它隐藏为无代价恢复。

## 数据阶段与资源

[输入复用与预算](../../experiments/v2801-input-cache-compatibility.json)核对父兼容模块字节和实际缓存身份：训练／验证／测试仍使用v2401的价格历史输入，没有新增整套原始行情缓存。`v1601_*`及`v2401_*`文件是冻结父实现，保留其原名；运行新方案使用`v2801_train.py`。

1. 流式写出624维FP32表示，按原样本行号回填，包含所有实际请求键；训练标签缺失只影响后续树拟合。
2. 释放原始常驻行情，再按65,536行读取表示并构造量化训练矩阵。日期和原标准化标签单独记录，树训练不重复运行父网络。
3. 每个验证块通过便携Torch树评测，选择后再提取测试表示；恢复测试阶段不重新拟合树。

训练7,760,000行、验证936,000行、测试1,000,000行的表示与数值元数据预计新增 **24,395,136,000字节，约22.72GiB**，另加评测键、清单和运行输出。缓存身份不包含树超参数或新版本号；相同表示应继续复用冻结的表示／缓存模块，避免因模型名称复制数据。

主机量化构建的当前空间检查约 **18.53GiB + 2GiB预留**，原始行情已在此前释放。GPU ELLPACK数据负载估计约 **9.00GiB**，这是数据本身的估计，**不是峰值显存**；转换、工作区和原生缓存另计，完整矩阵峰值仍待正式环境检验。Torch峰值记录不包含XGBoost原生分配，不能据此报告总显存。

## 训练交接与产物

训练入口是[v2801_train.py](v2801_train.py)，运行逻辑见[v2801_run.py](v2801_run.py)；保持一次正式运行、预留2GiB。它是“固定网络提取表示，再训练树”的新训练类型，不是AdamW／EMA更新网络。

- `scripts/check-candidate-device.py --solution-id v2801 --device cuda`会调用本版合成预检：检查父编码批量、原生树更新、便携推理和同设备分块恢复。GPU检查由训练session在间隙执行。
- 恢复预检要求树拓扑、阈值、叶值、缺失方向及其他树状态完全一致；不参与预测的增益统计`loss_changes`单独按`rtol=1e-6、atol=1e-7`核验，并记录差异，不能据此声称原生模型全部统计逐位相同。
- `feature-caches.json`记录三阶段表示来源；`initial-validation.json`记录零树父基准。
- `history.csv`的epoch表示25棵树的验证块，另有明确的`boosting_rounds`。训练MSE与正式IC口径分开记录。
- `best.pt`／`last.pt`包含完整配置、父网络和树数值数组、原生模型JSON、实际树训练配置及抽样状态。权重来源标记为`frozen_parent_ema_plus_boosted_trees`，不虚构本版EMA更新。
- 参数量统计为冻结神经参数加选中树的阈值／叶值数，树的实际数量和数值参数另列。达到完整验证／测试后才进入比较；只按验证IC选迭代次数。

本地默认已安装固定版本XGBoost，训练依赖见[requirements-training.txt](requirements-training.txt)。正常导入、平台预测和Notebook调试不会启动训练。显式[复现入口](v2801_reproduce.py)从授权原始数据重建预处理、重新训练父网络，再执行树阶段；这是最终两阶段方法的复现，不重放之前所有研究尝试。

## 推理与检查

[默认入口](v2801_predict.py)和[fast入口](v2801_predict_fast.py)按股票日共享父编码；树在Torch中按块批量遍历，不要求平台安装XGBoost。采用模型IO中的数值分裂阈值、缺失方向和叶值，树自身初始值固定为零，父初始预测只加一次。

实现检查覆盖[冻结表示与树转换](../../tests/test_v2801_core.py)、[量化及恢复](../../tests/test_v2801_training.py)、[完整合成流程](../../tests/test_v2801_entrypoint.py)和[平台入口](../../tests/test_v2801_predict.py)。包括全部1,200棵树的声明预算、阈值相等／相邻浮点值／缺失分支、文本张量恢复、八时点因果性、动态股票池和部分请求。原生与便携推理存在浮点归约顺序差异，按已声明容差核验，不声称跨后端逐位相同。

上述检查用于实现与恢复语义；正式效果及资源观测如下。平台实际运行尚未验证。

## 冻结结果与平台材料

完整结果见[比较摘要](../../experiments/v2801-neural-tree.json)、[月份与时点差距](../../experiments/v2801-ic-target-gap.json)及[信号代理](../../experiments/v2801-signal-diagnostics.json)。按验证IC选中第1个提升块的25棵树，共训练5块125棵后早停；未扫描前24棵树的测试表现。选中树含2,689个数值参数，连同冻结网络共2,644,432个。

双集覆盖及最低截面覆盖均为100%，未定义相关截面为0。相对父版，IC提高的月份为验证4／6、测试5／6，时点为5／8、6／8；Rank IC提高的月份仅0／6、1／6，时点仅0／8、2／8。因此它是按验证IC晋级的单次候选，不能宣称排序普遍改善或统计显著。父网络此前也用同一验证期选择；测试期已经参与持续研究观察。距双集IC 0.25目标仍分别差 **0.141651／0.129448**，不自动扩展树深度或学习率扫描。

一次正式运行墙钟约 **15.45分钟**，复用已有父权重，不包含父版训练成本。其中树更新及验证合计22.60秒，训练／验证／测试表示提取约420.23／47.71／51.06秒，量化构建211.07秒；不能把22.60秒当作完整运行时间。新表示数值数组24,395,136,000字节，约22.72GiB，另有键与清单。采样进程峰值RSS约52.03GiB；整卡显存采样峰值约5.36GiB，包含其他进程且可能漏掉短峰值，不等于本进程独占峰值。配置预留2GiB，但采样最小主机可用内存仅约240MiB，配置值不能作为持续保留的实测保证。

**诊断损失记录限制：**父评估缓存的`targets`是零占位数组，原运行的评估`primary_mse_loss`因此不是实际标准化标签MSE。[独立审计](../../experiments/v2801-evaluation-loss-audit.json)确认训练目标有效，正式本地IC、Rank IC、原始标签MSE／MAE及验证选模使用真实`keys.vwap_return`，未受影响；选中模型真实标准化标签MSE为验证0.988586、测试0.987107。冻结历史、权重及源码保持原样，审计单独补充；不拿占位损失与训练损失比较。

平台材料为[Notebook](../../submissions/v2801-neural-tree-s42-fast/v2801-submission.ipynb)和[参数JSON](../../submissions/v2801-neural-tree-s42-fast/v2801-model.json)，同目录两个文件分别8,863及48,040,217字节，均小于50MB。推理使用股票日共享编码，选中树以纯Torch执行，不需要XGBoost。实际文本权重逐张量位精确恢复、隔离两文件八时点合成推理及独立训练源码导入通过，21行fast／逐样本最大差为\(5.96\times10^{-8}\)。按简化约定未重跑长行情或速度基准，未验证实际平台执行；[清单](../../experiments/v2801-neural-tree-s42-fast-submission.json)保存验证范围与指纹。平台上传由用户执行。
