# 持续模型研究与训练交接

[文档目录](README.md) · [开发约定](development.md) · [训练 session 提示词](training-session-prompt.md) · [机器可读约定](../experiments/research-policy.json)

依据用户于 2026-10-20（UTC+08:00）的明确授权，本轮持续研究到用户叫停。研究 session 负责模型构造、分析和改进；另一个 session 独占正式训练调度。这里的持续授权覆盖后续 ready 候选，不再逐版本请求训练许可，也不套用技能的默认单次实验总预算。每个候选仍只安排一次正式训练，失败不通过改 run_id 自动重试。

## 目录与交接状态

沿用仓库已有的 `solutions/<version>/`，不另建 `solution/`。同一研究方向使用已有系列：v10x 为 Patch Transformer，v20x 为 Mixer，v30x 为分层 GRU，v40x 为监督目标研究，v50x 为训练方法研究，v60x 为日内卷积与跨日递推结合的结构研究，v70x 为股票日共享编码、跨频交互与辅助监督的组合研究，v80x 为完整截面的股票集合交互，v90x 为当天多频信息与因果输入组织，v100x 为训练分布适应与行情条件多模式预测，v110x 为原始字段结构编码，v120x 为收益分布辅助监督，v130x 为完整截面目标与训练组织；新的大方向使用未占用的系列。损失、监督、采样等改变记录在具体方案中；不把只有种子变化的运行冒充新模型结构。

新版本在独立目录实现完整本地训练、推理及复现代码，使用 `experiment.json` 描述研究假设、预期成本、父版本、唯一 run_id、训练入口、优先级及 `draft / ready / retired` 状态。只有完成实现检查并记录代码指纹后才发布 ready；训练 session 不启动 draft。ready 后源文件保持冻结，修订研究变量使用新版本；临时错误的必要修复须留下记录并重新检查。

v140x 单独记录已有冻结模型的组合；v1401 无新增训练，已由专用入口完成双集评估并退出普通训练调度。其 `retired` 只表示不再作为基础模型训练任务，已有改善候选及平台材料仍有效；不会将零训练组合伪装成新的训练 epoch。

v150x 为完整市场时空表征系列：序列编码、股票轴交互和因果时点轴共同建模，完整上下文不按监督标签删股票。它使用单独的网络及检查，不作为 GRU 分支或冻结组合的局部扩展。

运行状态以 `outputs/runs/<run_id>/manifest.json`、冻结权重和验证／测试产物为准，不能只看目录存在、历史 README 或进程退出码。已经完成的运行直接复用。v201／v301 原有调度只被接管一次，不能与新的扫描控制器并发启动。

## 待评测数量与容量控制

未完成本地双集评估的候选计入积压，包括 draft、ready、正在训练、正在评估及待处理的中断／失败。已明确撤销的 retired 候选不计入，但保留原因。历史已完成版本不重复排队；迁移来源运行不作为另一个新实验。

严格按用户给出的阈值：未评测数 **大于 3** 时停止构造；进入等待后，仅在未评测数 **小于 3** 时恢复构造，等于 3 时仍等待。依据用户 2026-10-21 的最新要求，研究 session 的例行训练结果及容量检查改为**每 3 小时一次**；完成、异常通知和主动询问仍及时处理，普通 batch／epoch 进度不唤醒研究 session。该调整不改变另一个训练 session 的调度频率。等待期间可分析已经完成的结果，不积累未登记的隐藏候选。

正式训练由另一个 session 串行执行。研究 session 的实现检查使用 CPU 合成数据；如需 GPU 默认批量性能检查，应由训练 session 在模型间隙执行，以免抢占在训模型的显存和吞吐。

CPU 检查和平台入口核验也占用主机内存。启动前核对训练阶段及可用 RAM，接近训练侧内存预留阈值时推迟重型核验，优先使用小型合成数据和定向测试。候选测试可通过 `JYC_TEST_SOLUTIONS=v306,v501` 限定遍历版本，未设置时运行全部登记候选；readiness 报告记录实际测试范围，不能把定向通过解释为其他版本重新验证通过。

## 效果、效率与平台额度

目标是平台最终表现。本地仍用固定 `local-v2-ic` 协议和官方原始标签比较，按验证 IC 选 checkpoint；训练目标、损失和采样可设计新版本，但不能把改了评估标签后的分数与旧结果直接相减。每个完成训练的候选均评估验证与测试，失败和未改善结果同样保留。

用户于 2026-10-21 补充要求提高单轮改进幅度：优先构造有共同目标的组合方案，允许适当扩大模型及训练时间，不继续以大量窄幅单变量试验作为默认策略。组合先比较整体效果；只有后续确需归因时再安排有目的的消融，不假称每个组件都有效。

用户于 2026-10-22 进一步要求优先发现遗漏的大方向，不能持续围绕现有一条或几条路线做局部改进。后续设计先检验任务目标、市场联合结构、输入表达及表征学习等底层假设，依据[研究缺口图](research-gap-map-20261022.md)选择有区分度的方案；不预设必须沿用 GRU，也不自动扩展已有分支或等权组合。已发布候选保持冻结，既有改善候选的交付继续收尾。

每次新改进前，先检索近期论文并结合已完成实验形成设计依据。核验原始论文、正式发表／预印本状态、时间划分、是否按测试集选模、有效基线、多种子、代码与数据可复现性和任务匹配；论文的新颖性或会议名称不能替代证据。来源记录版本、访问日期和时区。首轮筛选及组合设计见[文献与研究方向](research-directions-20261021.md)；后续候选说明链接对应依据，并区分论文结果、本地结果和研究假设。

初始工程目标可扩展至约 100 万—500 万参数、预计 6—12 小时训练及逐轮验证；这是研究设计范围，不是新增硬预算，须由 GPU 预检及实际吞吐校正。明确收益证据可支持进一步扩大。记录参数量、每轮训练与验证耗时、样本吞吐、峰值资源、停止原因，分清迁移、缓存构建、等待与训练时间。保留验证 IC 选模及动态早停，不为用满时间强行延长训练；避免无证据地复现 v9 的超大展平路径。

本地筛选综合比较验证 IC、IC／Rank IC 稳定性、逐月和日内表现、覆盖、与已有模型的互补性以及效率。换手和组合指标如在本地实现，明确标注代理口径，不能当作平台 BARRA 与交易成本的复刻。优良候选再从冻结源码和权重生成平台材料。验证 IC 未创新高但有其他明确平台价值的候选单独记录理由，保留原本地判定。

用户进一步要求后续所有平台提交使用 fast 逻辑，并简化转换检查。默认按股票日复用切窗和可共享编码；同构模型以逻辑等价审查和既有证据为主，必要时补少量针对性测试，不重复跑长区间性能与预测对照。正式模型的本地验证／测试保持原协议。具体规则见[开发约定](development.md#比较与导出工具)，已验证实例见 [v303 加速](v303-inference-fast.md)。这是后续模型的部署要求，不改变已运行模型的冻结训练配置。

用户于 2026-10-21 进一步明确：**停止主动查询平台成绩，只按本地结果改进模型并生成优良候选的平台提交材料；平台成绩更新由用户同步。** 例行监控仅检查本地训练结果和队列容量，不查询平台接口。平台反馈不作为本地研究的等待条件；用户提供新反馈后，区分执行问题与模型效果，再按可确认的对应关系记录。

平台每天最多 5 次提交，以用户同步的当日提交情况管理额度；每天的 5 次是上限，不要求用满。平台提交由用户执行，研究 session 提供优先级、完整材料和理由，不自动上传或操作私榜选择。

## 停止与恢复

用户叫停研究后，不再构造和发布候选，并停用本 session 的容量唤醒；除非用户同时要求停止训练，不擅自终止另一个 session 的在训进程。再次恢复时先核对队列和实际产物，避免重跑。

用户于同日补充授权研究 session 根据进展执行 commit 与 push。以模型实现、必要测试、交接规则和有效冻结结论为提交单位，仅纳入有长期意义的修改；检查共享工作区，避免混入其他 session 的未完成工作。运行日志、临时检查、行情和凭据不入库。平台上传仍由用户执行。
