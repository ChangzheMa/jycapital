## 实测效果

2026-10-21（UTC+08:00），在同一台本机使用 CPU 4 线程、PyTorch 2.11.0，先后运行原版和加速版的完整预测请求。区间为 2024-12-16 至 2024-12-31，包含 12 个交易日、96,000 行预测。同期另一 session 的 GPU 训练继续运行，本次测量不使用 GPU。

| 项目 | 原版 | 加速版 |
| --- | ---: | ---: |
| 完整预测调用 | 204.095 秒 | 69.373 秒 |
| 切窗 | 82.839 秒 | 9.363 秒 |
| 模型计算 | 66.580 秒 | 9.527 秒 |
| 行情读取及 DataFrame 检查 | 16.647 秒 | 16.636 秒 |

| 进程峰值工作集 | 4.86 GiB | 3.22 GiB |

完整预测调用约加速 **2.94 倍**，耗时减少 **66.0%**，峰值工作集降低 **33.7%**。96,000 行的输出键及预测值逐行完全一致，最大绝对差为 **0**。行情读取时间基本相同，主要收益来自切窗和模型计算复用。JSON／源码装载另行计时；阶段计时存在嵌套，不能全部相加。

这是一次本地配对测量，不是平台耗时保证。平台数据跨度、硬件、查询速度以及新股票的历史统计准备都会影响总时间；未测量实际平台 GPU 运行速度，不能据此承诺一定满足平台运行时限。

## 计算复用方式

原版按预测样本取窗，同一股票一天的八个时点会重复提取 5／30 分钟历史、昨日 1 分钟历史，并重复执行大部分 GRU 编码。

加速版按股票日分组，每只股票只为请求内最晚时点取一次窗口。5／30 分钟分支编码一次；1 分钟日内单向 GRU 编码一次，再从八个截点对应的前缀状态读出。跨日递推和预测头仍使用原参数，09:30 仍读取昨日状态。未来状态不参与较早时点的输出，部分日内请求及动态股票池只返回原请求键。

窗口网格仅存储请求目标股票；原始行情读取、股票池时间对齐、完整截面归一化及动态历史回退保持原实现，因此不是通过减少归一化截面或输出股票来提速。继续使用原 FP16 输入舍入与 FP32 极值修复，模型计算为 FP32，没有量化或截短历史。

实现见 [共享编码](../solutions/v303/v303_fast.py) 和 [推理适配器](../solutions/v303/v303_predict_fast.py)。导出清单显式记录推理适配器覆盖；训练复现仍恢复冻结原模型与训练源码。

17 项 CPU 实现及导出检查通过，覆盖八时点原模型对照、未来扰动隔离、乱序及不完整请求、动态股票池、缺失值、FP16 溢出修复、文本权重、冻结源码依赖和原有数值容差。

独立双文件平台入口验证覆盖验证期 2024-01-02—2024-01-05 的 32,000 行及测试期 2024-12-30—2024-12-31 的 16,000 行。两段均与原 checkpoint 加冻结预处理数据的独立 CPU 输出完全一致；34 个权重张量逐位恢复，22 份训练源码恢复及导入通过，输出覆盖、键唯一性、有限性和类型通过。原有 `atol=2e-7、rtol=1e-4` 同后端标准没有放宽。
