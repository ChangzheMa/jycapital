## 本地检查

- 对照导出清单检查缺失、额外及重复文件、行数、字节数、内嵌导出标识、各表字段一致性及完整五档字段。
- 完整读取所有数据列并执行 Arrow 数据结构校验，不仅检查文件末尾的 Parquet 元数据。
- 检查 `(date, instrument)` 重复键、空键、日期是否超出文件所属月份、周末记录及非整分钟记录。
- 统计每列空值、浮点 NaN、正负无穷、零和负值；对 OHLC 范围、买一价格高于卖一等现象单独计数。
- 汇总逐日行数、日内时间分布，并检查 `instrument` 与 `instrument_id` 映射是否一对一。

异常值统计是需要解释的数据现象，不自动视为下载损坏。例如无成交、停牌、集合竞价等情形是否允许空 OHLC、零盘口或交叉报价，仍须结合源表定义确认。脚本保留原值，不自动填充、裁剪或去重。

## 内容摘要与平台比较

算法标识为 `jycapital-canonical-columns-sha256-v1`。两端使用同一实现，逐月按 `date`、股票键排序；键有重复时，追加全部其他字段作为排序条件，保留重复记录的重数。随后为每列计算 SHA-256，并组合为月份及全表内容摘要。所有行、所有列都参与计算。

规范编码保留数值类型、时间精度、字符串内容和每个位置的空值标记，使用固定字节序；字符串另编码每个值的字节长度。分类字段先解码为原值，忽略 Arrow / Parquet 的分块、压缩方式、文件元数据及原始行序。不同 NaN 位模式视为相同 NaN，浮点 `+0` 与 `-0` 视为相同数值。该摘要比较的是这些规则下的逻辑数据内容，不比较 Parquet 文件字节是否完全相同。

比较时应同时确认算法版本、表清单、月份数、总行数、schema、逐日行数摘要及 `content_sha256`。任一月份丢失、重复或任一字段内容变化，都会改变全表内容摘要（不考虑 SHA-256 的极小碰撞概率）。如果全表摘要不同，完整报告保留逐月、逐列摘要，可定位差异。源表在下载后更新，也会导致差异；多次查询没有跨表、跨月快照保证。

运行报告 `status = complete` 仅表示所有计划的验证任务执行完毕。正确性需要结合异常统计和平台比较结果判断。长期验证摘要中的 `status = match` 则表示本次两端内容比较已通过。
